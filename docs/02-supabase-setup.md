# Supabase 연동 — 설정 안내

> 소요 시간: 약 10분 / 비용: 무료 플랜으로 충분
> SQL 파일 3개는 **작성·검증 완료** 상태입니다. 실제 PostgreSQL 16 + PostGIS 환경에서 실행해
> 테이블 생성, 권한 정책, 샘플 데이터 적재까지 전부 통과하는 것을 확인했습니다.

---

## 0. 준비된 것 / 사용자가 할 것

| 작업 | 상태 | 담당 |
|---|---|---|
| 테이블·인덱스·트리거 SQL | **완료** `supabase/migrations/001_schema.sql` | — |
| RLS 권한 정책 SQL | **완료** `supabase/migrations/002_policies.sql` | — |
| 전국 샘플 데이터 SQL | **완료** `supabase/seed.sql` | — |
| Supabase 가입 · 프로젝트 생성 | 미완 | **본인** |
| SQL 3개 실행 (복사 → 붙여넣기 → Run) | 미완 | **본인** |
| 키 2개 전달 | 미완 | **본인** |
| 앱의 Supabase 어댑터 코드 | 미작성 (키 받은 뒤 작성) | — |

계정 로그인이 필요한 작업만 본인이 하시면 됩니다.

---

## 1단계 — 프로젝트 생성 (3분)

1. `https://supabase.com` → **Start your project** → GitHub 또는 이메일 가입
2. **New project** 클릭
3. 입력값:

| 항목 | 값 | 주의 |
|---|---|---|
| Name | `haru` | |
| Database Password | 임의의 강한 비밀번호 | **따로 저장하십시오.** 분실 시 재설정 필요. 저에게 보낼 필요 없습니다 |
| Region | **Northeast Asia (Seoul)** | 생성 후 변경 불가. 다른 지역이면 응답이 눈에 띄게 느려집니다 |
| Plan | Free | |

생성까지 1~2분 걸립니다.

---

## 2단계 — PostGIS 켜기 (1분)

좌측 **Database → Extensions** → 검색창에 `postgis` → 토글 ON.

거리 계산과 반경 검색에 사용합니다. 켜지지 않으면 알려주십시오. 확장 없이 동작하는 대체 SQL을 드리겠습니다.

---

## 3단계 — SQL 실행 (3분)

좌측 **SQL Editor → New query** → 파일 내용을 전부 붙여넣고 **Run**. **반드시 순서대로** 3번 반복합니다.

| 순서 | 파일 | 하는 일 | 성공 시 보이는 것 |
|---|---|---|---|
| 1 | `supabase/migrations/001_schema.sql` | 테이블 8개, 인덱스, 트리거, 검색 함수 | `Success. No rows returned` |
| 2 | `supabase/migrations/002_policies.sql` | RLS 권한 정책 28개, 접근 권한 | 표가 출력됨 — **8개 테이블 모두 `rls_enabled = t`** 확인 |
| 3 | `supabase/seed.sql` | 데모 계정 25개 + 전국 공고 약 650건 | 건수 표 2개 출력 |

3번 실행 후 나오는 표가 대략 이렇게 나오면 정상입니다.

```
 항목         | 건수
--------------+------
 계정         |   25
 공고(전체)   |  658
 공고(모집중) |  525
 지원         |  975
 근무완료     |  135
 후기         |  104
```

오류가 뜨면 **메시지를 그대로 복사해서 보내주십시오.**

---

## 4단계 — 이메일 확인 끄기 (1분)

좌측 **Authentication → Providers → Email** → **Confirm email** 토글 **OFF**.

켜둔 채로 두면 회원가입마다 메일 인증을 받아야 로그인이 되어 팀원 테스트와 발표 시연이 번거롭습니다. 실제 서비스라면 켜두는 것이 맞습니다.

---

## 5단계 — 키 2개 확인 (1분)

좌측 **Project Settings → API** 에서:

| 항목 | 형태 | 저에게 전달 |
|---|---|---|
| **Project URL** | `https://xxxxxxxx.supabase.co` | **O** |
| **anon public key** | `eyJhbGciOi...` 로 시작하는 긴 문자열 | **O** |
| ~~service_role key~~ | `eyJ...` (secret 표시) | **X — 절대 금지** |

> `anon` 키는 브라우저에 공개되는 것이 정상이며, 권한은 RLS가 통제합니다.
> `service_role` 키는 **모든 권한을 우회**합니다. 저에게도, 팀 단톡방에도, GitHub에도 올리지 마십시오.

### 보내주실 내용

```
Project URL: https://________.supabase.co
anon key: eyJ________
PostGIS 활성화: 성공 / 실패
SQL 실행 결과: 1번 ___ / 2번 ___ / 3번 ___
```

이걸 받으면 `src/services/supabase/` 어댑터를 작성하고 `.env` 설정까지 끝내겠습니다.

## 검증된 내용

SQL 파일은 실제 PostgreSQL 16 + PostGIS 3 환경에서 실행해 아래를 모두 확인했습니다.

**스키마·데이터**

- 테이블 8개, 인덱스, 트리거 생성 성공
- 전국 123개 시·군·구에 공고 658건 적재
- 평균 평점 트리거가 후기 등록 시 자동 재계산

**근접 검색 (`search_jobs` RPC)**

- 의정부 기준 반경 5km에서 10건 조회, 최근접 748m
- 거리순 정렬 정확
- 반경 밖 공고 제외 정확

**RLS 권한 정책 — 실제로 막히는지 테스트**

| 시나리오 | 결과 |
|---|---|
| 근무 완료자가 후기 작성 | **성공** (정상 동작) |
| 근무 안 한(대기중) 건에 후기 작성 | **차단** — RLS 정책 |
| 같은 건에 후기 중복 작성 | **차단** — UNIQUE 제약 |
| 타인 명의로 후기 작성 | **차단** — RLS 정책 |
| 사용자가 스스로 관리자 되기 | **차단** — 트리거 |
| 남의 공고 지원자 목록 조회 | **0건** (정상) |
| 본인 지원 내역 조회 | **87건 조회됨** (정상) |
| 마감된 공고에 지원 | **차단** — RLS 정책 |

> 검증 중 **테이블 GRANT 누락**을 발견해 `002_policies.sql`에 추가했습니다.
> RLS만 있고 GRANT가 없으면 `permission denied for table ...` 오류가 납니다.

## 예상 문제와 대처

| 증상 | 원인 | 대처 |
|---|---|---|
| `permission denied for table ...` | GRANT 누락 | 2번 SQL 재실행 |
| `extension "postgis" is not available` | PostGIS 미활성화 | 2단계 수행 |
| 로그인은 되는데 공고가 안 보임 | RLS 정책 누락 | 2번 SQL 재실행 |
| 회원가입 후 로그인 안 됨 | 이메일 확인이 켜져 있음 | 4단계 수행 |
| 공고가 0건 | seed 미실행 | 3번 SQL 실행 |
| `relation "profiles" already exists` | 이미 실행함 | 정상입니다. 재실행해도 안전하게 작성돼 있습니다 |

## 팀원 공유 시 주의

- `.env` 파일은 **Git에 올리지 말고** 메신저로 내용만 공유합니다 (`.gitignore`에 이미 포함).
- 팀원 4명이 같은 Supabase 프로젝트를 바라보면 데이터가 공유됩니다. 이것이 mock 모드와의 결정적 차이입니다.
- 무료 플랜은 일정 기간 접속이 없으면 프로젝트가 일시 정지될 수 있습니다. **발표 전날 한 번 접속해 활성 상태를 확인**하십시오.
- `seed.sql`은 비밀번호가 공개된 데모 계정(`haru1234`)을 만듭니다. 실제 사용자를 받는 서비스에는 실행하지 마십시오. 되돌리려면 파일 맨 아래 초기화 블록의 주석을 풀고 실행하면 됩니다.
