# HARU

> 내 주변의 하루 일자리, 믿을 수 있는 후기와 함께

위치 기반 일용직·단기 아르바이트 구인구직 웹서비스. 학교 팀 프로젝트용으로 개발되었습니다.

---

## 1. 실행 방법 (3단계)

필요 환경: **Node.js 18 이상** (`node -v`로 확인)

```bash
# 1. 의존성 설치
npm install

# 2. 환경 변수 파일 생성
cp .env.example .env      # Windows: copy .env.example .env

# 3. 개발 서버 실행
npm run dev
```

브라우저에서 `http://localhost:5173` 이 자동으로 열립니다.
**외부 API 키나 데이터베이스 설정 없이 바로 동작합니다.**

| 명령 | 설명 |
|---|---|
| `npm run dev` | 개발 서버 실행 |
| `npm run build` | 타입 검사 + 프로덕션 빌드 (`dist/`) |
| `npm run preview` | 빌드 결과 미리보기 |
| `npm run typecheck` | 타입 검사만 수행 |

### 데모 계정 (비밀번호: `haru1234`)

| 역할 | 이메일 | 용도 |
|---|---|---|
| 구인자 | `employer1@haru.test` | 공고 등록·지원자 관리·근무 완료 처리 |
| 구직자 | `worker1@haru.test` | 지원·후기 작성 |
| 관리자 | `admin@haru.test` | 신고 처리·콘텐츠 숨김·샘플 데이터 초기화 |

로그인 화면 하단의 버튼을 누르면 입력란이 자동으로 채워집니다.

## 2. 현재 동작 방식 (중요)

이 프로젝트는 **두 가지 데이터 모드**를 갖도록 설계되었습니다. `.env`의 `VITE_DATA_SOURCE`로 전환합니다.

| 모드 | 상태 | 설명 |
|---|---|---|
| `mock` | **구현 완료** | 브라우저 `localStorage`에 저장되는 샘플 데이터로 동작. 외부 설정 0 |
| `supabase` (배포본 기본값) | **구현 완료** | 실제 PostgreSQL + PostGIS + RLS 권한 검증 |

배포된 사이트는 `supabase` 모드로 동작합니다. 로컬에서 외부 설정 없이 화면만 확인하려면 `mock` 모드를 쓰십시오.

**mock 모드의 한계:**

- 비밀번호가 브라우저 저장소에 평문으로 저장됩니다. 로컬 개발 전용이며 배포용이 아닙니다.
- 데이터가 브라우저별로 분리됩니다. 다른 기기·브라우저에서는 보이지 않습니다.
- 권한 검증이 클라이언트 코드에서 이뤄집니다.

**supabase 모드의 권한 구조:**

- 인증은 Supabase Auth(GoTrue)가 처리하며 비밀번호는 서버에서 해시 저장됩니다.
- 모든 테이블에 RLS(Row Level Security) 정책이 적용되어, 권한 검증의 최종 방어선이 데이터베이스입니다.
- 후기 작성은 `status = 'completed'` 인 지원 건의 당사자만 가능하도록 DB 정책으로 강제됩니다. 클라이언트를 우회해도 뚫리지 않습니다.

서비스 계층(`src/services/*.ts`)의 함수 시그니처는 두 모드가 동일하므로, 전환 시 화면 코드는 수정되지 않습니다.

**구현하지 않은 기능** (UI에도 표시하지 않았습니다): 결제, 급여 지급·정산, 실시간 알림, 주소 검색(지오코딩), 이미지 업로드.

## 3. 지도에 대하여

지도 엔진을 **외부 지도 SDK 없이 직접 구현**했습니다. (`src/components/map/HaruMap.tsx`)

| 구분 | 담당 |
|---|---|
| 투영(Web Mercator), 타일 배치, 드래그·줌, 마커 클러스터링, 반경 원, 축척, 좌표 선택 | **직접 구현** |
| 배경 지형지물(도로·건물·역 이름) | OpenStreetMap 래스터 타일 (오픈 데이터) |

도로·건물 형상은 측량 데이터라 코드로 생성할 수 없습니다. 어떤 지도 서비스도 이 데이터는 외부에서 가져옵니다. HARU는 **배경 타일만** 오픈 데이터를 쓰고, 좌표 계산과 상호작용은 전부 자체 코드로 처리합니다.

**왜 카카오 SDK가 아닌가**: 카카오맵 API 무료 쿼터는 개발자 계정의 첫 번째 활성화 앱에만 제공되며, 하위 테스트 앱은 하루 100건으로 제한됩니다. 팀원이 각자 키를 발급하면 개발 중 지도가 멈춥니다. OSM 타일은 **키·도메인 등록이 없어** 4명이 즉시 동일하게 개발할 수 있습니다.

**다른 지도로 교체하려면** `HaruMap.tsx`의 `TILE_URL` 한 줄만 바꾸면 됩니다. (VWorld, 카카오 등 — 단 키 발급과 도메인 등록이 필요합니다)

**OSM 타일 이용 정책 준수 사항** (구현 완료):
- `https://tile.openstreetmap.org/{z}/{x}/{y}.png` HTTPS 주소 사용
- 지도 우측 하단에 저작자 표시 노출
- 화면에 보이는 타일만 요청 — 사전 대량 수집·오프라인 저장 없음

**오프라인·차단 환경 대비**: 타일을 받지 못하면 자동으로 좌표 격자 배경으로 전환되어 마커·반경·좌표 선택은 그대로 동작합니다.

**남은 한계**: 주소→좌표 변환(지오코딩)은 제공하지 않습니다. 공고 등록 시 **지도를 클릭해 좌표를 지정**하는 방식으로 대체했습니다.

행정동 경계선을 덧그리려면 `public/geo/boundaries.geojson`을 추가하십시오 (`public/geo/README.md` 참고). 없어도 오류는 발생하지 않습니다.

## 4. 폴더 구조

```
src/
├─ types/            공통 타입·상태값 (팀 전체 공유, 임의 변경 금지)
│   ├─ enums.ts        상태값·카테고리·한국어 라벨
│   └─ database.ts     Profile / JobPost / Review 등 도메인 타입
├─ services/         데이터 접근 계층 (화면은 이 함수만 호출)
│   ├─ types.ts        Result<T> · 오류 코드
│   ├─ auth.ts         인증
│   ├─ jobs.ts         공고 · 근접 검색
│   ├─ applications.ts 지원 · 채용
│   ├─ reviews.ts      후기 · 평점 집계
│   ├─ community.ts    게시글 · 댓글 · 좋아요
│   ├─ reports.ts      신고 · 관리자
│   └─ mock/           샘플 데이터 생성기와 저장소
├─ features/         화면 간 공유 상태
│   ├─ auth/           AuthContext · 라우트 가드
│   └─ location/       위치·지역 선택 상태
├─ components/
│   ├─ ui/             공통 UI (버튼·입력·모달·로딩·빈 상태)
│   ├─ layout/         앱 레이아웃 · 네비게이션
│   ├─ map/            HaruMap (자체 구현 지도)
│   ├─ job/            공고 카드
│   └─ review/         별점 표시·입력
├─ pages/            라우트별 화면
├─ constants/        지역 목록 등 상수
└─ lib/              좌표·포맷 유틸
```

## 5. 주요 기능 테스트 시나리오

아래 순서대로 따라가면 핵심 기능이 모두 동작하는지 확인할 수 있습니다. 발표 시연에도 그대로 사용할 수 있습니다.

### 시나리오 A. 구직자 — 탐색부터 지원까지
1. 홈에서 지역을 `서울특별시 강서구`로 둔 채 **현재 위치로** 버튼을 눌러 봅니다. 권한을 거부해도 지역 기준으로 정상 동작하는지 확인합니다.
2. `주변 일자리` → 필터에서 **내일**, 직종 **물류·상하차**, 반경 **3km** 선택 → 결과 수가 변하는지 확인합니다.
3. 정렬을 **급여순**으로 바꿔 정렬이 바뀌는지 확인합니다.
4. 지도에서 마커를 눌러 요약 카드가 뜨는지, 클러스터(숫자 마커)를 누르면 확대되는지 확인합니다.
5. 공고 상세 → `지원하기` → 로그인 화면으로 이동 → `worker1@haru.test`로 로그인 → **원래 공고로 돌아오는지** 확인합니다.
6. 지원 후 같은 공고에 다시 지원하면 중복 지원이 차단되는지 확인합니다.

### 시나리오 B. 구인자 — 공고 등록부터 채용까지
1. `employer1@haru.test`로 로그인 → 우측 하단 `공고 등록`.
2. 폼을 채우고 **지도를 클릭해 근무 위치를 지정**합니다. 위치를 지정하지 않고 제출하면 오류 메시지가 뜨는지 확인합니다.
3. 등록 후 `마이페이지 → 등록한 공고 → 지원자 관리`.
4. 지원자를 **승인** → **근무 완료 처리**.
5. `모집 마감`을 누르면 목록에서 사라지고 상세에서는 "모집이 마감되었습니다"로 바뀌는지 확인합니다.

### 시나리오 C. 후기 권한 검증 (핵심 차별화)
1. 구직자 계정으로 `마이페이지 → 지원 내역`.
2. **대기중** 상태의 지원에는 후기 작성 버튼이 없는지 확인합니다.
3. 시나리오 B에서 근무 완료 처리된 건에만 `후기 작성` 버튼이 나타나는지 확인합니다.
4. 후기 작성(5개 항목 별점 + 재근무 의향 + 10자 이상) → 저장.
5. 해당 업체의 공고 카드·상세에서 **평균 평점이 즉시 갱신**되는지 확인합니다.
6. 같은 지원 건에 후기를 다시 작성하려 하면 차단되는지 확인합니다.

> 개발 편의 기능: `.env`의 `VITE_ENABLE_DEV_TOOLS=true`일 때 지원 내역에 `[개발용] 근무 완료 처리` 버튼이 보입니다. 구인자 계정 없이 후기 흐름을 테스트할 때 사용하고, 배포 시에는 `false`로 바꾸십시오.

### 시나리오 D. 커뮤니티·신고·관리자
1. 아무 계정으로 `커뮤니티 → 글쓰기` → 카테고리 **주의 정보** 선택 후 등록.
2. 댓글 작성, 좋아요 토글.
3. 다른 사람의 글에서 `신고` → 사유 선택 후 접수.
4. `admin@haru.test`로 로그인 → `관리자` → 신고 목록에서 **숨김 처리** → 일반 사용자 화면에서 글이 보이지 않는지 확인.

### 시나리오 E. 반응형·상태 화면
1. 브라우저 창을 360px까지 줄여 레이아웃이 깨지지 않는지 확인합니다. (모바일에서는 하단 탭 네비게이션, 지도/목록 토글)
2. 반경을 1km로 줄여 결과가 0건이 되게 만들면 **빈 목록 안내**가 뜨는지 확인합니다.
3. 로그아웃 상태에서 `/my` 주소로 직접 접근하면 로그인 화면으로 유도되는지 확인합니다.
4. `admin`이 아닌 계정으로 `/admin`에 접근하면 권한 없음 화면이 뜨는지 확인합니다.

## 7. 배포

정적 SPA이므로 Vercel에 그대로 올라갑니다. 저장소를 Vercel에 연결하면 `main` 브랜치에 푸시할 때마다 자동 재배포됩니다.

| 항목 | 값 |
|---|---|
| Framework Preset | Vite |
| Build Command | `npm run build` |
| Output Directory | `dist` |

**Vercel 환경 변수 (4개)**

| 이름 | 값 |
|---|---|
| `VITE_DATA_SOURCE` | `supabase` |
| `VITE_SUPABASE_URL` | Supabase 프로젝트 URL |
| `VITE_SUPABASE_ANON_KEY` | publishable(anon) 키 |
| `VITE_ENABLE_DEV_TOOLS` | `false` |

`vercel.json`의 rewrite 규칙이 모든 경로를 `index.html`로 넘기므로, `/jobs` 같은 주소에서 새로고침해도 404가 나지 않습니다.

> **service_role 키는 어떤 경우에도 환경 변수에 넣지 마십시오.** `VITE_` 접두사가 붙은 값은 전부 브라우저 번들에 포함됩니다. anon 키는 공개를 전제로 설계된 키이며, 실제 접근 제어는 RLS가 담당합니다.
